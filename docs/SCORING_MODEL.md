# 岗位匹配评分模型

总分 100，权重由 `config/scoring.yaml` 控制：核心内容 25；ERP/IT/流程 20；可迁移经验 15；行业/软件 10；语言 10；地点/远程 8；年限 5；学历/证书 3；工作许可 2；发展价值 2。

每个维度输入 0.0–1.0，并必须附证据：0 表示无支持，0.5 表示部分支持，1 表示完全支持。脚本按权重计算，再应用显著风险扣分。缺失评分默认 0，不把未知当匹配。

| 等级 | 分数 | 建议 |
|---|---:|---|
| A | 85–100 | 强烈建议申请 |
| B | 75–84.99 | 建议申请 |
| C | 65–74.99 | 有条件申请 |
| D | 50–64.99 | 优先级较低 |
| E | 0–49.99 | 不建议申请 |

扣分/否决包括缺失强制证书、无法支持母语级德语、深度开发要求、无高级管理经验、缺少监管执照、纯销售/纯开发、地点不可行和工作许可不兼容。否决标志不会隐藏原分，而会要求人工确认。

分析必须区分硬性要求、雇主偏好、可学习差距、可迁移经验、可通过表达改善的差距和无法通过改写解决的能力缺口。输出总分、等级、明细、优势、差距、风险、建议、语言、定制价值和待确认信息。

示例：在岗位 JSON 中提供 `dimension_ratings` 后运行 `python scripts/score_job.py data/jobs/<job>.json --write`。
